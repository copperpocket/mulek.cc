# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Deployment and git workflow

- **Pushing to `master` deploys to production.** A Dokploy instance rebuilds mulek.cc whenever `master` changes. Day-to-day work happens on `dev`, which gets merged into `master` through PRs. PRs use `.github/pull_request_template.md`: a plain-English title naming the biggest changes, then what's in the release, the commit list, and an after-deploy checklist. Merge with "Create a merge commit".
- **Don't commit, branch, or push unless the user explicitly asks.** Leave changes in the working tree.
- **`ROADMAP.md` is the running improvement list.** Check items off, or add new ones, as part of the same change.
- **Commit messages use Conventional Commits:** `type(scope): short description`, where type is `feat`, `fix`, `docs`, `style`, `refactor`, `test` or `chore`. See `.git-commit-template.txt`.
- **Stage the exact files for each commit.** Never commit a `HANDOFF.md` or `public/images/temp/`.

## Commands

The project uses Yarn 1; there's a `yarn.lock` and no `package-lock.json`. Run these from the repo root.

```sh
yarn install
yarn dev        # dev server on http://localhost:4321 (binds 0.0.0.0)
yarn build      # builds the Node server into dist/
yarn start      # runs dist/server/entry.mjs
yarn preview
```

There is no test suite, linter, or formatter configured. Restart the dev server after renaming or deleting files or changing the content schema, or it serves 500 errors from a stale cache.

## Environment

The `/api/contact` endpoint needs a `.env` file, which is gitignored. The rest of the site works without one.

- `PUBLIC_HCAPTCHA_SITE_KEY` is read in `src/pages/contact.astro` and exposed to the browser.
- `HCAPTCHA_SECRET_KEY`, `SMTP_HOST`, `SMTP_PORT` (default 2525), `SMTP_USER` and `SMTP_PASS` are server-only and read in `src/pages/api/contact.js`.
- These are `import.meta.env` reads, so they must exist at **build** time as well as at runtime. Astro compiles a variable that's present during the build into a runtime `process.env` lookup, but bakes in `undefined` for one that's missing, and setting it later won't help. If any are missing, the endpoint logs one `[contact] Contact form is disabled` line and answers every request with a generic 503.
- The endpoint rate-limits valid submissions to 5 per IP per hour, in memory. It takes the client IP from the last `X-Forwarded-For` entry (the one Dokploy's proxy adds). Field limits are mirrored as `maxlength` in `contact.astro`. Visitors only ever see generic error messages; details go to the server log.

`astro.config.mjs` sets `server.allowedHosts: ['mulek.cc']` on purpose: the user reaches the dev/preview server through that hostname.

## Architecture

- **Rendering:** `output: 'server'` with the `@astrojs/node` standalone adapter, so every page is rendered on each request. Anything random generated in frontmatter changes on every page load.
- **Styling:** Tailwind v4 via `@tailwindcss/vite`, with no `tailwind.config` file. Theme tokens (`accent`, `body`, `body-dark` and others), custom variants and shared component classes all live in `src/styles/global.css`:
  - Dark mode is class-based: `@custom-variant dark (&:where(.dark, .dark *))`.
  - `accent` (lavender) and `highlight` (pink, from the sun) change with the theme: the `@theme` values are the darker light-mode versions (readable at 4.5:1 or better on the light background), and `html.dark` swaps in the lighter ones. Lavender is the main color for links, buttons and active states; `highlight` is the hover color (`hover:text-highlight`, `hover:bg-highlight`) and is used for the category tags and the logo's ✦. Use `text-accent`/`bg-accent` and the colors follow automatically; `theme(colors.accent)` in CSS would bake in the light value, so use `var(--color-accent)` there. Text on a solid accent button uses `text-on-accent` (white in light mode, near-black in dark mode), never `text-white`.
  - Panels and forms that sit on the starfield use `bg-panel dark:bg-neutral-900`. `panel` is a solid lavender tint, so the stars don't show through; don't use a translucent `bg-accent/20` for a panel. Sub-page panels also get `card-edge`, an orchid-to-lavender border that fades out down the sides (it reads its fill from `bg-panel`, or white with `bg-white`). The home page panels use `panel-edge panel-edge-sun` instead, a 4px edge that follows the sun behind them.
  - Height-based variants `xshort`, `short`, `tall` and `xtall` exist alongside the usual width breakpoints.
  - Size popups and full-screen elements with `dvh`, not `vh`: `vh` measures the screen with the mobile address bar hidden, so it's taller than what's visible. For hover animations on `translate-*` or `scale-*`, use `transition-[translate,scale,...]`; `transition-transform` doesn't animate them in Tailwind v4.
  - Fonts are bundled with the site through Fontsource packages (imported at the top of `global.css`), never loaded from Google Fonts: Lexend for body text (`--font-sans`), Outfit for headings, the header nav and the menu (`--font-heading`, applied to `h1`–`h6`, `.nav-link` and `.home-menu-links`), and JetBrains Mono for code-style text (`--font-mono`).
  - `@tailwindcss/typography` styles blog post bodies through `prose`.
- **Import alias:** `@/*` resolves to `src/*`, set in `tsconfig.json`.
- **Page layouts:**
  - `MainLayout.astro` holds `<head>`, including the canonical URL and the Open Graph/Twitter preview tags (props: `image`, a path under `public/` defaulting to `/og.png`; `type`, set to `article` on posts and projects; `noindex` for the 404 page), the inline theme setup script that prevents a flash of the wrong theme, and Astro's `<ClientRouter />` page transitions.
  - Pages compose their own shell, usually `<Starfield />`, `<Header />`, content and `<Footer />`, and each imports `global.css` itself.
  - The content wrapper uses one of two shared classes from `global.css`, never its own padding: `.page-main` for short pages (Projects, Blog, Contact, 404), which center in any spare height on tall screens, or `.page-article` for long reading pages (About, write-ups, posts), which always start at the top. Both are mobile first. On `/projects` the results area is locked to its full height so filtering doesn't shift the centered page.
  - `Header.astro` is `fixed`, with a spacer element below it holding its place. A bundled script sets `data-scrolled` once the page scrolls past 24px; the scoped `<style>` switches between the tall, transparent top state and the compact scrolled state (solid background, accent line). The script runs once per full load, so it doesn't stack listeners across `ClientRouter` navigations.
  - The home page (`index.astro`) is the exception: it has no `Header`, just `SiteMenu` in the top-right corner. `SiteMenu.astro` is one button that opens the site links, outside links and the theme toggle: full screen on phones, a small card dropping from the button on wider screens. Sub-pages use it on phones in place of the header's nav bar. Both read the nav links and outside links (GitHub, Bluesky, RSS) from `src/config/links.js`, as does the Contact page.
- **Client scripts and page transitions:** because of `ClientRouter`, page scripts must initialize on `document.addEventListener('astro:page-load', ...)`, not on the initial run alone. There are two ways scripts are loaded:
  - Bundled `<script>` tags inside components.
  - Plain modules in `public/scripts/` imported by absolute path, for example `import "/scripts/contactFormHandler.js"`.
- **Theme:** `localStorage.theme` is either `light` or `dark`, falling back to `prefers-color-scheme`, and `html.dark` is toggled to match. That's set in one place, an inline script in `MainLayout`'s `<head>` that runs before the page paints and again on `astro:after-swap`. `components/Theme.astro` is only the toggle: it switches the class, saves the choice and dispatches a `themechange` event. Its animation CSS is a local copy in `src/styles/theme-toggle.css`, so the site makes no third-party requests.
- **Content collections** (`src/content/config.js`): both are legacy `type: "content"` collections, so `entry.id` includes `.md` and `entry.slug` doesn't. Routes and links always use `slug`. Unknown slugs rewrite to `pages/404.astro`.
  - **Blog** (`src/content/blog/`, served at `/blog/<slug>`): `title`, `description` and `pubDate` are required; `author`, `tags` and `image` are optional. `pages/blog/[slug].astro` 301-redirects old `/blog/<name>.md` URLs, and redirects old `/blog/<name>` URLs to `/projects/<name>` when that project exists, because the project write-ups used to be blog posts. New posts start from `src/content/blog-post-template.md`. Dev logs (`dev-log-NN.md`, a plain record of each round of site changes: what changed, what we learned, the commits) start from `src/content/dev-log-template.md` and keep its sections, order and tag list exactly. Check every claim against the real git log and PR list before publishing. Any post written by AI starts its title with `[AI] `. Frontmatter dates are midnight UTC, so format them with `timeZone: "UTC"` or they show a day early.
  - **Projects** (`src/content/projects/`, served at `/projects/<slug>`): the frontmatter is the card (`title`, `description`, `pubDate`, `category`, `tags`, plus optional `url` and `github`; `image` is only the link preview) and the body is the write-up. `/projects` shows each as a `ProjectTile`: the whole card links to the write-up, with a mono `CATEGORY · YEAR` line and the tags as plain text. An optional `current: true` makes a project the home page's "Current Project" (otherwise the newest is used, computed in `AboutSummary.astro`) and the wide featured card at the top of `/projects`. `category` must be one of `projectCategories` in `config.js` (Web, Infrastructure, Games), which also sets the filter-button order. New projects start from `src/content/project-template.md`.
  - **Sitemap:** `/sitemap.xml` (`pages/sitemap.xml.js`) lists the fixed pages from a `staticPages` array plus every blog post and project. Add new top-level pages to that array. `public/robots.txt` points to it.
  - **RSS:** `/rss.xml` (`pages/rss.xml.js`) combines blog posts and projects, newest first. It's generated at build time and uses `site` from `astro.config.mjs` for absolute links.
- **Logo:** the `>m_` prompt mark and the `mulek✦cc` wordmark are hand-built SVGs that share one set of letter shapes (5-unit round strokes, the same x-height). Masters live in `public/images/logo/` (`mark.svg`, `tile.svg`, `wordmark.svg`). The tile is just the `m` on a lavender rounded square, because the full `>m_` didn't read at 16px; `public/favicon.svg` is a copy of it. `components/Wordmark.astro` (top left in `Header.astro` and on the home page) and `components/LogoMark.astro` (the footer, and the 404 page with `blink`, which blinks the underscore like a cursor) inline them, colored by `--logo-ink` and `--logo-star` in `global.css`. `public/og.png` (the link preview) and `public/apple-touch-icon.png` are screenshots; if the logo changes, regenerate them from a temporary page.
- **Pet photos:** each pet's photos live in `public/images/pets/<pet>/`, listed in `src/data/pet-photos.json`; clicking a pet's name in `AboutSummary.astro` shows a random one. That intro paragraph (with each pet's age, and a 🎂 on their birthday) is shared by the home page and the About page. Add photos only through `yarn pet-photos` (`scripts/pet-photos.mjs`): drop originals in the gitignored `photos-inbox/<pet>/`, and the script re-encodes them with no metadata (no GPS location, camera or dates), checks every photo on the site, and rebuilds the JSON. The repo is public, so never commit an original photo. To edit a photo, crop the original kept in `photos-inbox/.added/<pet>/`, drop the result in the inbox and delete the old site copy; run `yarn pet-photos` after any add, edit or delete, so the JSON never points at a missing file.
- **Background (`Starfield.astro`):** a single `<canvas>` draws twinkling stars (a few rare red and blue ones), comets (now and then a pair, rarely a small meteor shower), and, with `grid`, the scrolling synthwave grid below a horizon (plus, with `sun`, a big sun half-sunk into it, striped unless `stripes={false}`, drawn over the stars so none show through; it also tells elements marked `data-sun-edge` where its gradient falls across them, so `.panel-edge-sun` borders can follow it). `constellations` (up to 12, or a `[min, max]` range rolled on each page load) adds randomly shaped constellations that draw themselves in one after another, with an optional `haze`, and `nebulas` (same) adds soft clouds of gas in colors of their own (in light mode they darken the sky like ink); they fade in slowly unless `nebulaFade={false}`. How busy the sky is lives in `src/config/sky.js`: `homeSky` for the home page and `pageSky` for every other page (counts, haze, nebula fade and time between comets), spread into `<Starfield>`. Each gets a random spot anywhere in the open sky, clear of the sun and of anything marked `data-starfield-avoid`, like the home page panels, theme toggle and menu button; one that doesn't fit is skipped. The site header is marked `data-starfield-avoid="static"`: measured but not watched, so the sky doesn't rearrange as the header shrinks on scroll. Nebulas and finished haze are painted once onto their own layers and reused, so high counts stay cheap. It's fixed to the viewport by default, at the screen's full height with the mobile address bar hidden (`h-lvh`), so the bar sliding in and out on scroll doesn't resize the canvas and rearrange the sky (any resize places the constellations and nebulas again, which looks like the sky refreshing); the home page passes `fixed={false}` so it fills the hero instead. Colors come from the `--starfield-*` variables in `global.css` and are re-read on the `themechange` event. Light mode uses deeper star colors plus `--starfield-alpha` (an opacity multiplier) so the stars don't wash out on the light sky. Grid proportions, star color odds, comet looks and the pair and shower odds are constants at the top of its script. Headless browser screenshots only run a frame or two of animation, so comets don't show up in them. With `prefers-reduced-motion` it draws one still frame.
- **Dev helper:** `TwSizeIndicator` shows the current Tailwind breakpoint, but only in development.
